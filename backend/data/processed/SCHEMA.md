# Processed Data Schema

Documentation for all artefacts produced by the ingestion and feature-engineering
pipeline. All files live under `backend/data/` relative to the project root.

Generated by: `src/ingestion/clean.py` and `src/features/engineer.py`
Source dataset: UCI Individual Household Electric Power Consumption (id=235)
Raw row count: 2,075,259 minute-level observations

---

## `data/processed/hourly_clean.parquet`

Produced by `python -m src.ingestion.clean`.

**Shape:** 34,169 rows x 8 columns
**Index:** `DatetimeIndex` (UTC, hourly frequency)
**Date range:** 2006-12-16 to 2010-11-26
**Compression:** Snappy (PyArrow)

### Cleaning steps applied

1. Minute-level data resampled to hourly (power columns averaged; sub-metering summed).
2. `Other_consumption` derived column added (see formula below).
3. Short gaps (<= 4 consecutive missing hours): forward-fill then backward-fill.
4. Long gaps (> 4 consecutive hours): rows dropped entirely.
5. Assertions: no NaN, monotonic index, no duplicate timestamps.

### Column reference

| Column | dtype | Unit | Aggregation | Description |
|---|---|---|---|---|
| `Global_active_power` | float64 | kW | mean | Household global minute-averaged active power |
| `Global_reactive_power` | float64 | kW | mean | Household global minute-averaged reactive power |
| `Voltage` | float64 | V | mean | Minute-averaged voltage at the meter |
| `Global_intensity` | float64 | A | mean | Minute-averaged current intensity |
| `Sub_metering_1` | float64 | Wh | sum | Kitchen energy (dishwasher, oven, microwave) |
| `Sub_metering_2` | float64 | Wh | sum | Laundry room energy (washer, dryer, fridge, light) |
| `Sub_metering_3` | float64 | Wh | sum | Water heater and air-conditioning energy |
| `Other_consumption` | float64 | Wh | derived | Unmetered appliance energy (see formula below) |

### `Other_consumption` derivation

```
Other_consumption = (Global_active_power * 1000) - Sub_metering_1
                    - Sub_metering_2 - Sub_metering_3
```

Values are clipped to zero to prevent negative consumption from measurement
rounding. Configured under `data.derived_column` in `configs/params.yaml`.

## `data/features/features.parquet`

Produced by `python -m src.features.engineer`.

**Shape:** 34,001 rows x 34 columns
**Index:** `DatetimeIndex` (inherited from `hourly_clean.parquet`)
**Date range:** 2006-12-23 to 2010-11-26 (first 168 warmup rows dropped)
**Compression:** Snappy (PyArrow)

The target column `Global_active_power` is retained in this file so that
train / val / test splits can be produced from a single artefact.

### Leakage invariant

Every feature at row `i` uses only data from timestamps strictly before
`index[i]`. All lag indices k >= 1; all rolling windows apply `.shift(1)`
before computing the window statistic.

### Feature groups

#### Target

| Column | dtype | Description |
|---|---|---|
| `Global_active_power` | float64 | Hourly mean active power in kW (forecast target) |

#### Calendar features (9 columns)

| Column | dtype | Description |
|---|---|---|
| `hour_of_day` | int64 | Hour of day (0–23) |
| `day_of_week` | int64 | Day of week (0=Monday, 6=Sunday) |
| `is_weekend` | int64 | 1 if Saturday or Sunday, else 0 |
| `month` | int64 | Month of year (1–12) |
| `is_holiday` | int64 | 1 if French public holiday, else 0 |
| `hour_sin` | float64 | sin(2π × hour_of_day / 24) — cyclical hour encoding |
| `hour_cos` | float64 | cos(2π × hour_of_day / 24) — cyclical hour encoding |
| `month_sin` | float64 | sin(2π × (month-1) / 12) — cyclical month encoding |
| `month_cos` | float64 | cos(2π × (month-1) / 12) — cyclical month encoding |

#### Lag features (4 columns)

All derived from `Global_active_power.shift(k)` where k >= 1.

| Column | dtype | Lag | Description |
|---|---|---|---|
| `lag_1h` | float64 | k=1 | Active power one hour ago |
| `lag_2h` | float64 | k=2 | Active power two hours ago |
| `lag_24h` | float64 | k=24 | Active power same hour yesterday |
| `lag_168h` | float64 | k=168 | Active power same hour last week |

#### Difference features (2 columns)

| Column | dtype | Formula | Description |
|---|---|---|---|
| `diff_1h` | float64 | lag_1 - lag_2 | 1-hour rate of change |
| `diff_1_25h` | float64 | lag_1 - lag_25 | 24-hour rate of change (rolling day-over-day) |

#### Rolling statistics (6 columns)

All windows applied to `Global_active_power.shift(1)` to prevent leakage.

| Column | dtype | Window | Statistic |
|---|---|---|---|
| `roll_mean_24h` | float64 | 24 h | Rolling mean |
| `roll_std_24h` | float64 | 24 h | Rolling standard deviation |
| `roll_max_24h` | float64 | 24 h | Rolling maximum |
| `roll_mean_168h` | float64 | 168 h | Rolling mean (one week) |
| `roll_std_168h` | float64 | 168 h | Rolling standard deviation (one week) |
| `ewma_12h` | float64 | halflife=12 h | Exponentially weighted moving average |

#### Sub-meter share features (5 columns)

Shares computed as `Sub_metering_i / Global_active_power`. Set to 0 when
`Global_active_power < 0.01 kW` to avoid division by zero.

| Column | dtype | Formula | Description |
|---|---|---|---|
| `sub1_share` | float64 | Sub_metering_1 / GAP | Kitchen fraction of total power |
| `sub2_share` | float64 | Sub_metering_2 / GAP | Laundry fraction of total power |
| `sub3_share` | float64 | Sub_metering_3 / GAP | Water heater / AC fraction of total power |
| `other_share` | float64 | 1 - sub1 - sub2 - sub3 | Unmetered appliance fraction |
| `sub3_lag24_diff` | float64 | Sub_3.shift(1) - Sub_3.shift(25) | Day-over-day change in water heater / AC |

### Column count summary

| Group | Columns | Count |
|---|---|---|
| Raw sensor / derived (from hourly_clean) | Global_active_power, Global_reactive_power, Voltage, Global_intensity, Sub_metering_1, Sub_metering_2, Sub_metering_3, Other_consumption | 8 |
| Calendar features | hour_of_day, day_of_week, is_weekend, month, is_holiday, hour_sin, hour_cos, month_sin, month_cos | 9 |
| Lag features | lag_1h, lag_2h, lag_24h, lag_168h | 4 |
| Difference features | diff_1h, diff_1_25h | 2 |
| Rolling / EWMA features | roll_mean_24h, roll_std_24h, roll_max_24h, roll_mean_168h, roll_std_168h, ewma_12h | 6 |
| Sub-meter share features | sub1_share, sub2_share, sub3_share, other_share, sub3_lag24_diff | 5 |
| **Total** | | **34** |

The modelling target is `Global_active_power` (first column of the raw sensor
group). All other 33 columns serve as input features to the Ridge and XGBoost
models.

## `data/processed/quality_report.json`

Produced alongside `hourly_clean.parquet` by `src/ingestion/clean.py`.

### JSON schema

```json
{
  "rows_before_cleaning": 35064,
  "rows_after_cleaning": 34169,
  "short_gaps_filled_hours": 123,
  "long_gap_rows_dropped": 772,
  "date_range": {
    "start": "2006-12-16 17:00:00",
    "end": "2010-11-26 21:00:00"
  },
  "column_stats": {
    "<column_name>": {
      "min": 0.0,
      "max": 11.122,
      "mean": 1.091
    }
  }
}
```

### Field descriptions

| Field | Type | Description |
|---|---|---|
| `rows_before_cleaning` | int | Hourly row count after resampling, before gap handling |
| `rows_after_cleaning` | int | Final row count after dropping long-gap rows |
| `short_gaps_filled_hours` | int | Number of hourly rows imputed by forward/backward fill |
| `long_gap_rows_dropped` | int | Number of hourly rows removed (gap > 4 consecutive hours) |
| `date_range.start` | str | ISO 8601 timestamp of the first retained hourly row |
| `date_range.end` | str | ISO 8601 timestamp of the last retained hourly row |
| `column_stats` | object | Per-column descriptive statistics for all numeric columns |
| `column_stats.<col>.min` | float | Minimum observed value (post-cleaning) |
| `column_stats.<col>.max` | float | Maximum observed value (post-cleaning) |
| `column_stats.<col>.mean` | float | Mean value (post-cleaning) |

## Temporal Split Reference

Used by `src/skills/temporal_split.py` and configured in `configs/params.yaml`:

| Split | Start | End | Approx rows |
|---|---|---|---|
| Train | 2006-12-16 | 2008-12-31 | ~17,800 |
| Validate | 2009-01-01 | 2010-06-30 | ~13,200 |
| Test | 2010-07-01 | 2010-11-26 | ~3,000 |

All splits are strictly chronological. No random shuffling is ever applied.
